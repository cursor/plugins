# 0.25.0

Changes an existing team needs from this release. Apply a plugin update checks only these items when Plugin version applied is older than 0.25.0 and the installed version is 0.25.0 or newer. A category that says none is not a change. Nothing here is applied without the person's yes.

## Skills this release changes

The plugin install brings these, so there is nothing to apply for them: Write a workflow skill (its workflow skill reference), Verify work, Set up Team Builder, Coach my bots, Build a bot (and its operating guide reference), Check my bots, Run the weekly bot review, Plan the work, Build my team (its team map check), Explain how it works (its principles file and guide), Apply a plugin update, and Team Builder operating guide. Hand off reopens a task it marked done and the note it sent, and gives their links. A check-back routine is named after what it waits on, reused when one with that name exists, and deleted as soon as the wait ends. Verify work's example shows a failed line, the fix, and the recheck, and its steps keep the rule for a check that can't run in one step. Set up Team Builder finishes only what's missing when Team Builder exists, and creates Weekly review prep only when no routine has that name. Coach my bots and Build a bot look a routine up by name before creating or changing one, and a profile fact message names the fact it replaces and gets a read-back. Coach my bots first proposes a field or a check when a bot got something wrong. Weekly review prep updates today's dated file when it exists and posts only what changed, and the second time the same thing is corrected, it becomes a skill update. The spot check runs only on request. Checklists are found by their folder, from the 0.15.0 baseline, and the team map check accepts helper files whose own folder a skill names by path. A workflow skill already in the person's library picks up the Hand off and check-back wording only when it is rewritten.

## Operating guide layout

The description in the operating guide skeleton is shorter, so it stays within 120 characters for any bot type. After the person's yes, in each bot type's operating guide whose description still reads `Follow whenever you are a <type> bot of this team and start any task; your job, skills, connectors, rules, and handoffs.`, with its type filled in, replace it with `Follow whenever a <type> bot of this team starts a task; its job, skills, connectors, rules, and handoffs.`, with the same type. Skip a description the person wrote or changed. Do not edit Team Builder operating guide here; it comes with the plugin.

## Routine form

Ask each bot to list its routines by name, exactly as saved. Where two routines on one bot share a name, propose keeping the one that matches the spec's Routines text and deleting the other. Where a check-back routine's wait has already ended, propose deleting it. After the person's yes, each bot deletes its own routine. Skip a bot with neither.
