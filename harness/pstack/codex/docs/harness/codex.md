# pstack in Codex

Apply this adapter to the bundled skills, playbooks, agent briefs, and guides. Follow current session instructions, repository rules, permissions, and tool schemas.

- A pstack slash command names a bundled skill. Read its sibling `skills/<name>/SKILL.md` directly when applying it from another skill. Users can select skills from the Codex skill picker. Paths to bundled files are relative to the plugin root.
- Use the session's plan tool for todolists and its user-input tool when available and appropriate. Use the shell for repository commands and search, subject to repository rules.
- Cursor Task and project workers refer to the session's supported delegation tools. Delegate only when authorized by current instructions. Use `agents/poteto-agent.md` and `agents/comment-sicko.md` as brief material when applicable. Supply only fields and model names confirmed by the current tool. Preserve read-only and isolation requirements. If a capability is unavailable, do eligible work in the current session.
- Whenever running a pstack skill, read the user's pstack role settings from `$CODEX_HOME/pstack/models.md` if present (default `~/.codex/pstack/models.md`). Apply those overrides to linked playbooks and delegated roles. This is the Codex mapping for the Cursor model rule throughout pstack. Include the resolved role and settings when handing work to a worker that cannot read this file.
- Run the shared setup-pstack workflow, including budget selection, migration, display and confirmation of all roles, validation and persistence. Write the confirmed rule to the mapped path, creating its parent directory if needed. Preserve the shared format, role names, ordered lists, duplicates and aliases. On subsequent runs read the existing rule before proposing changes.
- For an explicit model choice, store the exact available model ID and a space followed by its reasoning effort when supported. Interpret that pair as separate delegation settings. Preserve the shared fast Opus setting as a trailing `fast` token and pass the provider’s fast-mode option. If the required option is unavailable, ask before changing it. Show the provider, model and effort when offering choices. Use the shared budget ladder for the target effort. Only offer combinations supported by the available delegation tool. For unavailable families or vendors, show the unresolved role and ask for a replacement. Never silently collapse a panel or substitute a same-vendor cross-judge. Keep the shared workflow's vendor eligibility and user confirmation steps. Resolve `auto` and `inherit-parent` by inheriting the session settings. Recheck availability before delegation in a new session.
- Use available browser, terminal, and test tools to gather equivalent verification evidence. Use the session's approved PR tools or the forge CLI as appropriate. Handle existing review threads as ordinary forge review threads. Skip Cursor-only automation, Bugbot setup, transcript paths, and cloud-agent operations when there is no supported equivalent. Report resulting verification gaps.
- Use Codex session configuration and skill invocation. Do not write Cursor rules, create persistent jobs, change permissions, push, or merge solely because a playbook says to.
- In T3 Code: when T3 Code orchestration tools (`orchestrator_capabilities`, `delegate_task`) are present, read [the T3 Code overlay](./t3-code.md) once per session; share `$XDG_CONFIG_HOME/pstack/t3-models.md` (default `~/.config/pstack/t3-models.md`, taking precedence over `$CODEX_HOME/pstack/models.md`) for `/setup-pstack` and all role/panel overrides, and use `delegate_task` for cross-provider panel seats, `isolation: "worktree"` fan-outs, and canonical or `t3:` model specs; when absent, follow the standalone Codex rules above.
