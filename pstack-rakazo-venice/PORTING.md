Rule followed: keep every skill's name, intent, steps and wording; change only platform specifics. Anything not confirmed in docs or source is an inline `<!-- TODO(rakazo|venice): ... -->` marker. The changes were applied by `tools/port.py`, which logs every edit; the change log below is generated from that log.

## Layout

```
<skill>/SKILL.md (+ references, playbooks, scripts)   59 skills, same folder names as pstack/skills
agents/poteto-agent.md, agents/comment-sicko.md        pstack/agents (Rakazo turns agents/<name>.md into a skill that calls run_subagent)
LICENSE                                                pstack MIT license
```
To install as a Rakazo skills-only plugin, put the skill folders under `skills/` next to a `plugin.json` and `agents/`, push to a public GitHub repo, then **Skills → From GitHub → Preview → Add** (rakazo.com/docs/build-a-plugin). Not done here; nothing was installed.

## Kept on purpose (show up in a leftover grep)

- `~/.cursor/rules/pstack-models.mdc`: the fork's setup-pstack writes this file on the bot's computer for compatibility. Kept wherever a skill reads the rule.
- `.cursor/skills/verify-*` and `.cursor/skills/**/*-mode`: repo copies, because `skill_create` cannot carry reference files.
- worktree-cleanup: `.cursor/worktrees/…` and `~/Library/Application Support/Cursor` describe Cursor IDE files on the user's disk, not the agent platform.
- setup-pstack line 42: "the Cursor version of this skill" (fork text, migration note).
- poteto-help lines 48 and 116 name Cursor's `/loop` only to explain that routines replace it.
- `readonly __brand` in typescript-best-practices: TypeScript, not a tool flag.
- `is_background: true` in agents/poteto-agent.md: ignored by Rakazo, kept for fidelity.
- `disable-model-invocation`, `icon`, `color`, `paths` frontmatter: kept, ignored by Rakazo.
- Scripts under `scripts/` (TS, shell): unchanged. Rakazo won't install them. Some (`worktree-audit.sh`, `watch-pr`) mention Cursor paths internally.
