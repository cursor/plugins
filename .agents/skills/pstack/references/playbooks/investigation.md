# Investigation

Use this for a read-only question about how a system works, why it was built a certain way, or which option is better.

1. Confirm the question and identify the relevant files, history, docs, and available runtime evidence.
2. Trace the behavior through callers and data flow. Separate observed facts from inferences.
3. For a choice, compare realistic options and tradeoffs. Use a small experiment only when it can settle a factual uncertainty cheaply.
4. Answer with a short overview, how it works, where the relevant code lives, and important caveats. Link to files or sources you actually inspected.
5. Do not edit code unless the user asks to continue into implementation.
